## State, evidence and workflow boundaries

- Geographic grants are AP-1, AP-2, KA, KL, TG, TN and PY. KN input is normalized to KA by the application. AP, wildcard and All States are rejected as scoped grants. PY is consolidated into TN only by the existing attendance reporting engine; TN permission never silently grants PY. Central MIS is explicitly all-state.
- New MIS roles use `/api/reliance-retail/mis`. Verified JWT/profile identity supplies the actor. Legacy Retail/Fault/FO/Training/import APIs are unavailable to these roles; profile self-service remains available. Legacy roles keep their existing routes and the original `34cfa587` QPMSADMIN write gate. No editable JWT user_metadata supplies a grant.
- SQL independently checks active exact assignments, permitted module and canonical Store Code/state. Employee table/RPC writes are not granted. Direct service-role table access to new private data is also revoked; service-only RPCs own database commands. Super Admin alone can assign roles/states, and optimistic revisions/advisory locks reject concurrent stale changes.
- New MIS roles cannot use legacy direct Fault/FO table access or direct profile writes to change authority, create a second profile or escape their scope. Additive restrictive policies also limit their direct profile reads to their own account. Existing legacy employee policies remain intact; approved backend self-profile updates still use the existing whitelist.
- New Pest/Cleaning/Training records are explicitly MIS operational records, not fabricated FO attendance/site visits, historical completions or rewritten FO sessions. Existing canonical-linked sessions/submissions remain visible with their source kind. Unresolved legacy identities remain excluded rather than guessed.
- Images use the established FO-style two-phase private upload pattern: scoped draft intent, short-lived signed upload, exact stored size/type validation, then finalized metadata. The new bucket is private and max 5 MiB JPEG/PNG/WebP. Uploaded objects are immutable; managing draft evidence retires references and retains original objects/audit. Existing private buckets remain unchanged; new-role direct access is restricted, and scoped signing is required. New view links expire after 120 seconds. Revocation stops new reads/signing; already issued signed links can remain usable until expiry.
- Store name/city corrections require independent Super Admin review plus the existing Store Master write gate. Store Codes, geographic state, status, FO/Zone and AOP are not changed by this workflow. Nine missing AOP records remain unchanged. No missing mapping deactivates a store.
- Attendance reuses the existing bounded XLSX parser, lossless source audit, status-credit mapper, duplicate/daily-cap checks and explicit correction/version rules. Scoped uploads reject the whole file for foreign states/classes. Central MIS can upload mixed HK/MEPC through Imports. Cross-scope employee/day corrections are denied without disclosing foreign rows. AOP is never imported through this path. Targets use the existing decimal/effective-date engine and remain N/A for missing coverage; attendance targets require month-start-to-cutoff reporting.
- Legacy period/forward-only workflow bodies are copied into private MIS adapters with scope authorization. Installed originals and completed security functions are not renamed, replaced or reinstalled. Regenerate reviewed adapter source with `node scripts/buildRetailMisWorkflowAdapters.mjs`; only the combined migration is an installation artifact, never the proposal fragments.
- OOS state comes from every canonical Store Code; all stores/items in an order must reconcile. Cross-state quotation files are rejected in full even if the user has both states. Original source/hash and quotation atomicity remain intact. Existing reviewer checks and creator/reviewer separation remain mandatory. Retirement is an immutable tombstone only for QUOTED orders without financial/PO/delivery references/events. Original order/events/source remain; progressed orders cannot be deleted. An additive trigger prevents later updates through legacy APIs to a retired quotation.

## Rollback and containment

Before any assigned user is allowed in, deploy failure can use a reviewed application revert while leaving the additive schema private and unused. After assignments exist, reverting application code alone is unsafe because old code does not recognize the new roles. First have Super Admin revoke/restore the affected exact assignments through `rpc_retail_mis_assign` with current revisions and an audit reason; it restores recorded prior role/business/designation only when profile/assignment match. Retain auth IDs, passwords and history. Stop on classification drift instead of overwriting an unrelated change. Then use a reviewed GitHub revert preserving later unrelated commits.

Keep OOS activation false. Retain new audit/evidence/retirement records and restrictive protections. Never delete audit/source/business history, drop schemas with CASCADE, reinstall old security migrations, broaden bucket access, or undo financially referenced records as cleanup. Already issued view links expire naturally; incident containment of a live signed link needs the separately approved storage procedure. Retired quotations must remain protected even if the application is reverted.
