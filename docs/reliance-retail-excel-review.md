# Admin Excel review

Open Reliance Retail Attendance as an active ADMIN/QPMSADMIN, choose Upload Store Master & AOP, select the source .xlsx and click Validate and Preview. Review conflicts, then choose Export Excel review. Export always includes the full preview, regardless of the on-screen conflict filter.

The workbook contains Review guide, State summary, STORE UPLOAD REVIEW, Proposed stores, Existing codes, Conflicts, Identity decisions and Independent AOP. Headers are filterable and frozen. Source codes and SHA-256 values are text. Candidate numeric components remain numeric; missing values stay blank. Yellow decision cells are review requests, never authoritative approvals. Existing codes contains uploaded canonical matches, not every canonical record omitted from the upload; state totals retain the complete canonical counts supplied by the preview.

The source worksheet preserves its original literal headers, values and physical row numbers. Use the separate review tabs for filtering and sorting. Do not sort, insert or delete source rows when preparing a round trip. Provenance columns retain the ORIGINAL file checksum, row digest and source row; they are not a claim that an edited/exported file has the same checksum. Exported files have a different file checksum even when their literal source rows are unchanged.

Business reviewers must resolve official single code/name/geography, actual operating status and genuine ownership. No operating status, effective date, supervisor detail or AOP is inferred by export. Record actual identity decisions and evidence separately from final HK/MEPC allocations and periods in Independent AOP. An edited decision tab or source YES never inserts approval registry records.

Finalize the source worksheet only after business decisions are recorded. Re-upload that final workbook and validate again. Approvals must bind its final file SHA-256, source row number, literal row digest, code, named reviewer, evidence SHA-256, approval reference and validity. Ask the authorized SQL owner to record only the exact reviewed identity/AOP registry entries; the Admin dialog does not author registry approvals. Current new-identity import supports genuinely approved supervisor-only identities; actual FO-managed records require the established verified FO/zone workflow. Never invent supervisory details.

After SQL contract verification and exact batch review, use a fresh authenticated Admin preview. Check independent Store Master and/or AOP scopes only where their real registry approvals qualify, explicitly confirm review and select Confirm Import. Server-side Admin checks, closed activation gates, baseline/approval checks and stale-preview rejection remain unchanged. Source rows marked NO or lacking valid evidence remain pending. The current 854-row all-NO source has no safe first import batch. Do not enable activation gates just to test it.
